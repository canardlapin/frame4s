# frame4s 0.1.0

Status: release-candidate draft

frame4s `0.1.0` is the first public release of an immutable, typed local
dataframe library for Scala 3. The schema is a named-tuple type, a query is a
pure logical-plan value, and execution occurs within an explicit resource
scope.

## Included

- typed and dynamic projection, filtering, grouping, sorting, joins, limit,
  distinct, and `unionAll`;
- arbitrary atomic typed rename/drop request tuples, typed replace, multikey
  using joins, and independently configured typed sort keys;
- inner, left, right, left-semi, and left-anti joins;
- population variance and standard deviation;
- materialized typed row/cell reading, bounded rendering, row codecs, and
  `fromRows`;
- explicit `Table.takeOwnership` and `Table.retainFrom` batch-lifetime
  constructors, with structured partial-input cleanup;
- JVM and Scala.js source/runtime execution with streaming CSV/TSV adapters;
- optional JVM Apache Arrow IPC in the separate `frame4s-arrow` artifact;
- materializing `FrameRuntime` execution with `Auto`, `ReferenceOnly`, and
  `RequireColumnar` engine policies plus typed selection and fallback receipts;
- incremental streaming for source, project, filter, limit, and `unionAll`,
  with explicit blocking boundaries for aggregate, join, and sort;
- logical, collection-physical, and stream-physical explain;
- a cross-platform semantic oracle and reusable backend-conformance laws.

The reference interpreter remains the executable semantic oracle. A
materializing collect under the default `Auto` policy uses admitted in-process
columnar kernels and otherwise returns a typed fallback reason before reference
execution. `stream` deliberately uses the reference cursor so supported
operators can pull incrementally. The
[public-path replacement receipt](../benchmarks/receipts/2026-08-02-p4-public-path/summary.md)
verifies engine identity and fallback on the measured plans. It supports only
its stated same-machine comparison; `0.1.0` makes no broad “faster than” or
production-engine claim.

## Semantics

Integral arithmetic, including division and unary negation, is checked.
Required and nullable operands of the same physical width combine without
widening, with `Option` propagated into the result. Nullable booleans use SQL
three-valued `AND` and `OR`; `isTrue`, `isFalse`, `isNull`, and `isNotNull` are
total tests. The public API's planning capabilities are closed opaque tokens,
and `ColumnType` is sealed, so downstream Scala type-class instances cannot
authorize unsupported plans. The dynamic API validates the same expression
algebra with structured planning errors.

`Option[A]` is the only nullable typed-column representation. Null grouping,
NaN and signed-zero equality, floating aggregate behavior, row-order
guarantees, and normalization error preservation are specified in the semantic
constitution and exercised on JVM and Scala.js.

UTF-8 literals and scalars now contain a validated opaque `Utf8Value` rather
than a raw `String`. Checked constructors return `ValueError.NullUtf8`; direct
typed expression syntax rejects an ascribed null or `Some(null)` before a plan
exists. Row, schema, source-order, and column-array constructors classify
raw-null input explicitly, and Arrow UTF-8 decoding preserves the storage
check.

Logical explain now uses deterministic plan-local expression ordinals and a
linear operator legend. Literal contents and internal fingerprints are
redacted, and reused expression DAGs no longer produce recursively expanding
identifier strings.

Source and sink failures now keep one structured route across acquisition,
filesystem reads, strict UTF-8 decoding, arbitrary upstream streams, runtime
translation, writes, and finalization. Operational errors retain their causes
for explicit debugging, while public messages are bounded and never render
cause text or rejected values. Cancellation and fatal platform errors remain
outside the ordinary error ADTs. Portable CSV and TSV byte input now rejects
malformed UTF-8 rather than silently inserting replacement characters.

CSV and TSV now retain field quotedness through null decoding. Unquoted tokens
represent absence; quoted empty strings and quoted token strings remain data,
and sinks automatically quote every real value that could collide. The shared
parser has finite record, field, parser-chunk, batch, and diagnostic limits,
rejects excess schema width at its delimiter, handles transport BOM and blank
records explicitly, and reports encoded UTF-8 byte receipts on JVM and
Scala.js. `NullPolicy` replaces unrelated raw read-token and write-value
settings so round-trip behavior is one coherent contract.

Apache Arrow is no longer a transitive dependency of `frame4s-fs2`.
`frame4s-arrow` snapshots caller-owned input bytes when its source resource is
constructed and closes every decoded column if a later column or final batch
validation fails. The `0.1` typed timestamp contract is deliberately narrow:
only timezone-free microsecond Arrow timestamps are admitted. Other units and
timezone-bearing timestamp fields return structured errors. Arrow programs
must use `--add-opens=java.base/java.nio=ALL-UNNAMED`; the staged external
consumer runs with that same production option.

Named-tuple schema descriptors, field lookup, and row codecs now derive without
a field-count-sized inline or implicit chain. External JVM and Scala.js
consumers cover 32, 48, 128, 256, and 512 columns with default compiler
settings. The practical support envelope is 256 columns; 512 is a verified
compile-cost stress tier and is documented with its much higher task time.

## Known limitations

- The in-process columnar collect engine has no spill, distributed execution,
  or out-of-core contract. Unsupported plans use the visible reference
  fallback under `Auto`; the reference interpreter remains available as the
  correctness oracle.
- CSV/TSV runtime schema inference is intentionally absent. Typed ingestion
  requires an explicit schema; inference may later exist as a separate
  suggestion/receipt tool.
- Parquet, windows, reshape/pivot, temporal expansion, a hidden row index,
  implicit casts, and serialized-plan compatibility are not included.
- Scala Native is not supported.
- Arrow IPC is JVM-only and supports only timezone-free microsecond timestamps
  in `0.1`.
- Schemas above 256 columns are outside the practical compile-cost envelope.
  The 512-column court is retained as a stress regression, not a latency claim.
- The first release has a disclosed single-maintainer bus factor.

## Compatibility and migration

This is the first public release, so there is no prior public version to
migrate. `0.1.0` becomes the compatibility baseline for subsequent releases.
Patch releases in the `0.1.x` line follow the policy in
[`docs/compatibility.md`](../compatibility.md).

Code written against pre-release checkouts should note that dynamic
`variance` became `variancePop`, expression provenance is scope checked,
duplicate output names are rejected before execution, and source acquisition
now occurs through explicit runtime bindings. Arithmetic and comparison no
longer use open Scala numeric or ordering evidence; integral division, mixed
required/nullable operands, unary negation, and the corresponding dynamic
operations are part of the closed frame4s expression surface. The ambiguous
pre-release `Table.apply(batches)` constructor was replaced by the explicit
transfer and retain contracts.
Pre-release typed `renameAll` and `dropAll` calls now pass non-empty tuples of
`RenameRequest` and `DropRequest`; the arity-two-only signatures were removed.
Typed multikey using joins pass a tuple of `UsingKey` values, and heterogeneous
sorting constructs one `SortKey` per expression. All three forms lower to the
same plan nodes as their earlier restricted variants.
Pre-release code that directly constructed `LiteralValue.Utf8(String)` or
`ScalarValue.Utf8(String)` must use the total `.utf8` smart constructor. A
successful pattern match now yields `Utf8Value`; call `.value` to read its
non-null string.
Pre-release adapter code should also replace `SourceError.Open(String)`,
`SourceError.Close(String)`, and `SinkError.Write(String)` with the operational
Throwable-bearing cases. A closed source is `SourceError.Closed`. Match
`Read`, `InvalidUtf8`, and `Upstream` directly instead of parsing exception
messages.
Pre-release Arrow users must add the `frame4s-arrow` JVM coordinate explicitly
and remove Arrow-specific JVM options from programs that use only
`frame4s-fs2`.

## Evidence

The release candidate must link the exact semantic, staged-artifact, JVM JMH,
Scala.js, coverage, signing, security, and maintainer-continuity receipts. This
repository's private vulnerability-reporting channel is enabled and linked
from `SECURITY.md`. This draft deliberately contains no claim that unexecuted
remote CI, production signing, owner recovery, or publication has passed.

The latest repository-side rehearsals are the
[local release court](../benchmarks/receipts/2026-07-26-r6-local-court-final/summary.md)
and the
[isolated artifact rehearsal](../benchmarks/receipts/2026-07-26-r6-release-rehearsal-central/environment.properties).
Both identify a dirty development worktree, so neither substitutes for the R7
clean-commit court.

The tag-triggered publication workflow uses `sbt-ci-release` 1.11.2 with an
sbt 1.12.11 release runner so stable artifacts stage through the Central
Publisher Portal, as exercised by the
[disposable tagged-build route probe](../benchmarks/receipts/2026-07-26-r6-central-portal-route/summary.md).
The normal supported build court remains pinned to sbt 1.10.5. Production
credentials, owner recovery, signing, and public publication remain
unexercised until the owner preflight and R7 gates pass.
